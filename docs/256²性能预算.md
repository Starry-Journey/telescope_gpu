# 256² PD 性能预算

> 脚本：`scripts/benchmark_pd.py`
> 结果：`results/pd_benchmark.json`（可重建）
> 环境：WSL2 CPU、NumPy、单线程；不是 GPU 实测

## 1. 实测

`forward_psf_numpy` 5 帧 + 一个 BOBYQA（maxeval=10）：

| n | 5 帧前向 | 10 eval BOBYQA | 估算 100 eval |
|---:|---:|---:|---:|
| 64 | 0.0138 s | 0.102 s | 1.02 s |
| 128 | 0.0420 s | 0.371 s | 3.71 s |
| 256 | 0.1795 s | 1.673 s | 16.73 s |

单起点 100 次评估：64 约 1 s，256 约 16.7 s。  
40 起点串行：64 约 40 s，256 约 **669 s（11 min）**。

## 2. 结论

- 64×64 适合交互式 Web；
- 128×128 是交互/精度的折中；
- 256×256 不适合在 Web 请求里跑 40 起点 BOBYQA；
- 256² 必须做：
  1. **CNN/代理初值**，只留 3–5 个 BOBYQA 起点；
  2. **多进程/多 worker**：4/8 进程，按核数；
  3. **GPU 前向**：cuFFT/批量 star；
  4. **缓存**：相同 PSF/初值不重复跑；
  5. **渐进返回**：先给粗解，再异步精修。

## 3. 推荐配置

```text
交互预览: n=64, 2 starts, maxeval=200
认真反演: n=128, 5 starts, maxeval=400
256² 批处理: n=256, CNN top-3, 4 workers, maxeval=500
```

256² 4 worker 估算（100 eval/start）：

```text
16.73 s × 3 starts / 4 workers ≈ 12.5 s
```

实际还要加 FFT/内存/IO；预算按 20–40 s/样本留余量。

## 4. 复现

```bash
cd telescope_gpu
PYTHONPATH=. python3 scripts/benchmark_pd.py
```

## 5. 边界

- 这是 NumPy CPU 模型，不是主项目 CUDA `PhaseDiversitySolver`；
- 不含 CNN 推理/IO/调度；
- 256² 主报告是 15 星/5 帧/3 变量，当前脚本只测纯 PSF 前向；
- 上 GPU 前先用本表估 CPU 上限，避免在 Web 同步接口里跑 40 起点。
