# 光学仪器反演与控制框架技术说明

> 数据契约 · 正演/反演 · 灵敏度 · 控制


## 01 目标与范围

> 从“一个求解器”到“一条数据链”。

目标不是做万能科学计算平台，而是限定在光学仪器数据链：探测器帧 -> 定标/星表 -> 参数化观测 -> 反演 -> 灵敏度矩阵 -> 控制量 -> 不确定度。

*表 1-1  三个实例*

| 实例 | 数据 | 参数 | 决策 |
|---|---|---|---|
| 相位差 | 5 帧离焦 PSF | Z4/Z8/Z9 | BOBYQA 反演 |
| CCD 前端 | raw/定标帧 | 星点/WCS | 检测/天体测量 |
| 控制设计 | 目标像差 z | m2_focus/decenter/tilt | S → 最小二乘控制 |

通用性判据：新增一个实例只需写插件，不改 core；如果每次都要改 core，说明抽象不成立。

## 03 数据与参数契约

> 单位、边界、活动集是一等字段。

*代码 3-1  数据契约。*

```cpp
struct Image { int width,height; std::string unit; vector<float> pixels; };
struct Frame { Image image; double exposure_s; map<string,double> scalars; };
struct Observation { vector<Frame> frames; vector<double> defocus;
                     vector<StarPoint> stars; vector<double> truth; };
```

unit 必须是字段：相位差用 waves，CCD 用 e−/ADU，控制量用 mm/mrad；否则灵敏度矩阵的列不可比。

*代码 3-2  参数/控制空间。*

```cpp
struct ParameterSpec { string name, unit, group;
                        double lower, upper, prior_sigma; bool active; };
struct ControlAxis { string name, unit; int parameter_index;
                     double step, lower, upper; };
```

Zernike 索引、镜面模态、装调量都通过 spec 声明；核心不硬编码 Z4/Z8/Z9。


## 04 正演与反演

> y=F(p)+ε，p=p0+Bc。

相位差：PSF=|FFT(A exp(i2πφ))|²，φ 由 Zernike/离焦构成；控制：z=Au+z0；CCD：星点/质心/WCS 是可观测量。

*代码 4-1  模型/反演接口。*

```cpp
class ForwardModel {
  Observable evaluate(const ParameterBlock&, const Context&) const;
  bool jacobian(...) const;  // optional
};
class InverseSolver {
  Solution solve(const Observation&, const ParameterSpace&, const SolveOptions&);
};
```

Solution 带 cost/nfev/covariance/diagnostics；没有这些元数据，结果不可复现。


## 05 灵敏度与控制

> S_ij=∂z_i/∂u_j，最小二乘+Tikhonov。

中心差分：S[:,j]=(z(u+δ)-z(u-δ))/(2δ)。每个 control axis 独立 step；靠近边界退化为单边；对 S 做 SVD 得到 rank/condition/singular values。

*代码 5-1  控制目标。*

```cpp
min_u ||W(dz - S u)||^2 + lambda ||u-u0||^2
s.t. lower <= u <= upper
```

3×5 是欠定系统：rank=3，nullspace=2。最小范数解能复现目标 z，但不等于物理真值；这是科学结论，不是 bug。5×5 满秩才可精确恢复 u。

## 07 相位差适配与集成

> 只适配，不改数值。

PhaseDiversityInverseSolver 把 Observation 转成 telescope::FrameSet，调用 preprocess_frames，构造现有 PhaseDiversitySolver，最后映射 SolveResult。

*表 7-1  适配路线*

| 现有资产 | 适配方式 | 边界 |
|---|---|---|
| PhaseDiversitySolver | InverseSolver 适配器 | CUDA 可选，数值不变 |
| FITS 帧 | read_fits_observation → Observation | 复用现有 FITS 头/星表 |
| ForwardModelGPU | FourierOpticsForward（后续） | 需要 5 帧/星表 |
| pipeline | FITS bridge（后续） | 头/命名要统一 |
| numerics | SVD/QR/控制后端 | 已链接 |
| ml | 代理 ForwardModel（可选） | 64×64 不替代主求解器 |

优先级：先做 pipeline→FITS bridge，再做 ForwardModelGPU 适配，最后接 ml 代理；每一步都用 golden 数据回归。

## 10 参数与控制量对照

> 每个数字对应什么物理量。

*表 10-1  框架面板参数*

| 参数 | 含义 | 单位 | 怎么读 |
|---|---|---|---|
| Z4/Z8/Z9 target | 目标离焦/x 彗差/y 彗差 | waves | 希望系统达到的 z |
| δ | 中心差分步长 | mm / mrad | 太大非线性，太小数值噪声 |
| λ | Tikhonov 正则 | 目标²/控制² | 越大 u 越保守，残差可能变大 |
| S | S_ij=∂z_i/∂u_j | waves/(mm 或 mrad) | 行=目标，列=控制 |
| rank | 独立目标方向数 | — | 3×5 为 3 |
| nullspace | 不改变目标的控制组合数 | — | 5-3=2 |
| condition | 行空间条件数 | — | 小不代表 u 唯一 |
| u | 最小范数控制量 | mm / mrad | 欠定时不唯一 |
| residual | S·u - z_target | waves | 目标是否达到 |
| active_constraints | 触及边界的控制数 | — | 投影边界，不是 QP |

*表 10-2  M2 5-DOF 代理*

| 控制量 | 物理含义 | 单位 | 主要目标 |
|---|---|---|---|
| m2_focus | M2 轴向调焦/镜间距 | mm | Z4 离焦 |
| m2_decenter_x | M2 沿 x 平移 | mm | Z8 x 彗差 |
| m2_decenter_y | M2 沿 y 平移 | mm | Z9 y 彗差 |
| m2_tilt_x | M2 绕 x 倾斜 | mrad | 交叉项（代理） |
| m2_tilt_y | M2 绕 y 倾斜 | mrad | 交叉项（代理） |

当前 S 是 M2 5-DOF 的线性代理：m2_focus 主要给 Z4，decenter_x/y 主要给 Z8/Z9；tilt 与 Z4 的交叉项是 synthetic 占位，不是 Zemax 实测。接 ZOS-API 后必须重新生成 S。

FEA 面板的 gravity_deg/thermal_K 是环境变量灵敏度，不是 M2 5-DOF；3A Zemax 运动学、3B FEA 环境、3C 代理 5-DOF 三者不能混用。

*表 10-3  FEA 面板单位*

| 量 | 口径 | 单位 |
|---|---|---|
| FEA Z4/Z8/Z9 | 面形拟合系数 | nm |
| 环境 S 行 | Z4/Z8/Z9 | waves |
| 环境 S 列 gravity | 俯仰/重力方向 | deg |
| 环境 S 列 thermal | 温度变化 | K |
