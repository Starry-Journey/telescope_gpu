## 02 数学原理

> LU、QR/SVD、FFT、RK4 的假设/复杂度/失败模式。


### 2.1 线性方程组

部分主元 LU：P A = L U，解 L y = P b、U x = y；O(N³)。主元选绝对值最大行，抑制舍入放大。奇异/非方阵抛异常，不返回 NaN。


### 2.2 最小二乘

超定系统 min ||A x − b||₂。正规方程 AᵀA x = Aᵀb 会把条件数平方；本库默认列主元 Householder QR，并提供 SVD 版本处理秩亏/病态。复杂度 O(MN²)。


### 2.3 FFT

radix-2 Cooley–Tukey：X[k]=Σ x[n]exp(−2πi nk/N)，逆变换共轭/N；只接受 2 的幂，否则抛异常。复杂度 O(N log N)。


### 2.4 RK4

y' = f(t,y)，k1..k4 加权平均；局部 O(h⁵)，全局 O(h⁴)。标量返回 t/y，向量返回 t/states。固定步长，刚性问题应换隐式方法。


## 03 软件设计与代码注释

> 为什么这样写，注释写在哪。

*表 3-1  设计决策*

| 设计点 | 做法 | 原因 |
|---|---|---|
| 值语义/RAII | Eigen Matrix/Vector | 无裸 new，异常安全 |
| 异常 | invalid_argument/runtime_error | 尺寸/奇异/非 2 的幂显式失败 |
| PIC | POSITION_INDEPENDENT_CODE ON | pybind11 共享库可链接 |
| 依赖 | 系统包优先 + FetchContent | 可复现；WSL 避免误链 Windows conda |
| 注释 | 文件头 + 函数前 Doxygen | 输入/输出/异常/单位 |

*代码 3-1  文件头注释示例。*

```cpp
/// @file numerics.hpp
/// @brief Small, testable numerical core.
/// @throws std::invalid_argument wrong shape / non power-of-two FFT

```


### 3.2 构建与依赖

CMake 3.18+；Eigen/GTest/Google Benchmark/pybind11 优先 find_package，找不到用 FetchContent。WSL 下 find_package(GTest) 可能误链 Windows conda 的 gtest.lib，默认改为 FetchContent。静态库必须 POSITION_INDEPENDENT_CODE ON，否则 pybind11 共享模块链接报 relocation。

*表 3-2  CMake 选项*

| 选项 | 默认 | 作用 |
|---|---|---|
| TEL_NUMERICS_BUILD_TESTS | ON | GTest 10 项 |
| TEL_NUMERICS_BUILD_BENCH | ON | Google Benchmark |
| TEL_NUMERICS_BUILD_PYTHON | ON | pybind11 模块 |
| TEL_NUMERICS_ENABLE_ASAN | OFF | AddressSanitizer |
| TEL_NUMERICS_USE_SYSTEM_GTEST | OFF | 默认 FetchContent，避免跨平台 .lib |


### 3.3 错误处理

*表 3-3  异常契约*

### 4.2 测试设计

测试不是“跑通”，而是三件事：① 解析解（冲激谱、指数、谐振子）；② 独立实现对照（朴素 DFT、NumPy/Eigen）；③ 失败路径（奇异、非方阵、非 2 的幂、负步长）。ASan 构建在 WSL 下用单个 CTest 入口，避免 gtest_discover 与 ASan 冲突。


### 4.3 回归

任何实现改动后，先跑 10 项 GTest；接口/数值变化必须更新测试或说明原因。CI 的 numerics job 会重复这套。

### 5.2 Benchmark 方法

用 Google Benchmark 固定迭代/最小时间，避免单次计时噪声；solve 用 8/32/128 三个规模拟合 N³，FFT 用 256/1024/4096 拟合 N log N。结果只作量级参考，受 CPU/编译器/缓存影响。


### 5.3 Python ABI

pybind11 模块必须和编译时 Python 版本一致。本机用 /usr/bin/python3 3.8；若 CMake 找到 uv 的 3.12，需要显式指定 pybind11 cmake dir 或 PYTHON_EXECUTABLE。

### 5.5 边界

- 不处理稀疏矩阵/迭代法；
- FFT 只支持 2 的幂；
- RK4 固定步长，不适合刚性 ODE；
- SVD 版本更慢，按需使用。


### 5.6 与主项目的边界

数值库是通用核心，不读取 FITS/不包含望远镜参数；主项目的正演/反演仍用 CUDA 层。如果主项目需要使用本库的 LU/FFT，应通过明确接口复用，而不是复制实现。


### 附录A 关键源码

*代码 A-1  LU 与 FFT 的实现骨架。*

```cpp
Vector solve_linear(const Matrix& A, const Vector& b) {
  if (A.rows() != A.cols()) throw std::invalid_argument("not square");
  Eigen::FullPivLU<Matrix> lu(A);
  if (!lu.isInvertible()) throw std::runtime_error("singular");
  return lu.solve(b);
}

void fft(std::vector<Complex>& a, bool inverse) {
  if (inverse) for (auto& z : a) z = std::conj(z);
  fft_radix2(a);                       // bit reversal + butterflies
  if (inverse) { for (auto& z : a) z = std::conj(z) / a.size(); }
}
```
