# 光学仪器数据链：通用反演与控制框架（Design v1）

> 代码：`framework/`
> 示例：`./build-framework/framework/framework_demo results/framework`
> 目标：把“相位差求解器”升级为“数据 → 参数 → 正演 → 反演 → 灵敏度 → 控制”的可复用框架。

## 1. 设计目标

### 1.1 不是万能科学计算平台

限定在**光学仪器数据链**：

```text
探测器帧 -> 定标/星表 -> 参数化观测 -> 反演 -> 灵敏度矩阵 -> 控制量 -> 不确定度
```

不试图覆盖 CFD/ODE/任意科学计算。通用性由**三个实例**证明：

1. 相位差波前反演（5 帧、Z4/Z8/Z9、BOBYQA）；
2. CCD 天体测量前端（定标/星点/WCS）；
3. 3×5 影响矩阵控制（Z4/Z8/Z9 × uz/ux/uy/uα/uβ）。

### 1.2 核心判断

- **数据契约**：单位、掩膜、质量标志是一等字段；
- **模型契约**：`ForwardModel` 只负责“参数 → 可观测量”；
- **决策契约**：反演、灵敏度、控制互相独立，可替换；
- **可复现**：每次运行有 config/dataset 哈希、seed、版本、指标；
- **可验证**：解析解/合成真值/跨后端/回归。

## 3. 数据契约

```cpp
struct Image {
  int width, height;
  std::string unit;              // "e-", "ADU", "wave"
  std::vector<float> pixels;     // row-major
};

struct Frame {
  Image image;
  double exposure_s;
  std::map<std::string,double> scalars;  // defocus/theta/background
  std::string quality;
};

struct Observation {
  std::string id;
  std::vector<Frame> frames;
  std::vector<double> defocus;
  std::vector<StarPoint> stars;
  std::vector<double> truth;
};
```

**为什么把 unit 放在结构体里**：相位差用 waves，CCD 用 e−/ADU，控制量用 mm/mrad；单位错了，灵敏度矩阵的列就不可比。

## 4. 参数空间：自定义参数的核心

```cpp
struct ParameterSpec {
  std::string name, unit, group;
  double lower, upper, prior_sigma;
  bool active;
};

struct ControlAxis {
  std::string name, unit;
  int parameter_index;
  double step, lower, upper;
};
```

`ParameterSpace` 是参数的唯一来源；`ControlSpace` 是“允许动的子集”。

示例：

```cpp
ParameterSpace space({
  {"uz","mm","control",-0.5,0.5},
  {"ux","mm","control",-0.5,0.5},
  {"uy","mm","control",-0.5,0.5},
  {"ua","mrad","control",-0.5,0.5},
  {"ub","mrad","control",-0.5,0.5},
}, "secondary_mirror_5dof");
```

要扩展 Zernike/镜面模态/装调量，只加 spec 和插件，不改核心。

## 5. 正演模型

```cpp
class ForwardModel {
  virtual Observable evaluate(const ParameterBlock&, const Context&) const = 0;
  virtual bool jacobian(...) const { return false; }
};
```

- 相位差：`FourierOpticsForward`（包装 `ForwardModelGPU`），输出 5 帧；
- 控制：`SyntheticLinearForward`，输出 `z = A u + z0`；
- 后续：Zemax/poppy/代理模型都可以实现同一接口。

`NoiseModel` 提供 `variance(signal)`；`TargetExtractor` 把图像变成目标向量（Zernike 拟合、质心、PSF 矩等）。

## 6. 反演

```text
y = F(p) + ε,  p = p0 + B c
c* = argmin ||W(F(p0+Bc) - y)||² + λR(c)
```

`InverseSolver` 只暴露：

```cpp
Solution solve(const Observation&, const ParameterSpace&, const SolveOptions&);
```

`Solution` 包含 `values/cost/nfev/covariance/diagnostics`。现有相位差求解器通过 `PhaseDiversityInverseSolver` 适配，数值不变。

## 7. 灵敏度矩阵

```text
S_ij = ∂z_i / ∂u_j
```

中心差分：

```text
S[:,j] = (z(u_j+δ) - z(u_j-δ)) / (2δ)
```

实现要点：

- 每个轴独立 `step`；
- 靠近边界退化为单边差分；
- 对 S 做 SVD，输出 `rank/condition/singular_values`；
- 记录 model/extractor/context 的 provenance。

## 8. 控制求解

```text
min_u ||W(dz - S u)||² + λ||u - u0||²
s.t. lower ≤ u ≤ upper
```

`WeightedLeastSquaresControl`：

1. 加权 S、dz；
2. Tikhonov 增广 `[S; sqrt(λ)I]`；
3. SVD 最小二乘；
4. 边界投影；
5. 输出 `u/residual/cost/rank/condition/active_constraints`。

**3×5 是欠定系统**：rank=3，nullspace=2；最小范数解能复现目标 `z`，但不等于物理真值。这是科学结论，不是 bug。

## 10. 相位差适配

`framework/plugins/phase_diversity/phase_adapter.cpp`：

- 把 `Observation` 转成 `telescope::FrameSet`；
- 调用 `preprocess_frames`；
- 构造现有 `PhaseDiversitySolver`；
- 把 `SolveResult` 映射成 `instrument::Solution`。

只在 `TEL_BUILD_CUDA=ON` 时编译，CPU 框架不受影响。这样**数值结果仍由原求解器负责**，框架只做契约适配。

## 12. 科学原理

- 相位差：`PSF=|FFT(A exp(i2πφ))|²`，离焦项提供相位分集；
- Zernike：Z4 离焦、Z8/Z9 彗差，作为低阶模态基；
- 灵敏度：一阶泰勒 `z≈z0+S u`，S 由中心差分或解析/AD 得到；
- 控制：加权最小二乘 + 正则；欠定时 SVD 最小范数，零空间不可观；
- 不确定度：`Cov(u)≈σ²(SᵀW²S+λI)⁻¹`（后续）。
