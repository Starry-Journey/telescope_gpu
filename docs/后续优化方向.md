### P5-1 Qt 主路径去 `web` 化（P2 的前置）

现状：

| 事实 | 证据 | 风险 |
|---|---|---|
| Qt 的 6 个页签里 3 个直接 import `web.*`（涉及 4 个服务） | `desktop/qt_app.py`：`web.ccd_pipeline_service`、`web.fits_pipeline_service`、`web.pd_service`、`web.framework_service` | `web/` 标成 LEGACY，却是桌面运行时依赖；按 P2 删除 Web 会直接断功能 |
| `products/` 只承接了 FEA 和 ZMX | `desktop/qt_app.py` 中 `products.sensitivity`、`products.zemax` | 产品层没有成为唯一业务入口，目录分工与文档不一致 |
| Web API 是 Qt 的同层实现，不是薄适配器 | `web/api/main.py` 直接 import `web.*` 服务与 `ml.*` | 同一业务有两个入口，修改容易只改一边 |

建议迁移（先建新模块并保留旧模块 re-export，全部改完再删旧路径）：

```text
web/ccd_pipeline_service.py        -> products/ccd/service.py
web/fits_pipeline_service.py       -> products/ccd/fits_service.py
web/pd_service.py                  -> products/pd/service.py
web/framework_service.py           -> products/control/service.py
web/sensitivity_matrix_service.py  -> products/sensitivity/matrix_service.py
web/job_queue.py                   -> products/jobs/store.py
web/tests/*                        -> products/tests/*（按 products 子包拆分）
scripts/fits_defocus_test.py       -> 改 import products.ccd.fits_service
web/api/main.py                    -> 薄 HTTP 适配层：只做路由/校验/序列化
```

约束：

1. Web 的 URL 与 JSON 字段保持不变，避免外部脚本/旧页面同时断；
2. `pipeline/realistic.py` 目前 import `ml.traditional`，一并改为
   `products.optics.forward`（见 P5-2）；
3. 迁移和去重分成独立提交，不把“改路径”和“改数值”混在一起。

验收：

```bash
# 桌面/产品/管线/ML/脚本不再依赖 web（web/api 自身除外）
grep -rn "from web\|import web" desktop products pipeline ml scripts
# Qt 无头自检通过
QT_QPA_PLATFORM=offscreen python3 desktop/qt_smoke.py
python3 desktop/qt_app.py --self-test
# 产品层测试通过
python3 -m unittest discover -s products/tests -v
```

### P5-3 桌面工程化：拆分入口、worker 与任务协议

现状与建议：

| 问题 | 证据 | 建议 |
|---|---|---|
| `qt_app.py` 单文件 800+ 行，UI/绘图/导出/worker 分发混在一起 | `desktop/qt_app.py` | 拆为 `desktop/main.py`（CLI）、`desktop/app.py`（窗口/页签）、`desktop/worker.py`（`--worker` 分发）、`desktop/plots.py`、`desktop/tasks.py`（QProcess/临时目录/取消） |
| worker 子进程仍加载整个 Qt | `qt_app.py` 顶层 `from PySide6...`；`--worker` 走同一模块 | worker 模块不 import PySide6；`--worker` 只依赖 numpy/scipy/服务模块。用 `python -X importtime` 或 `sys.modules` 断言验证 |
| 取消后状态可能被 `finished` 覆盖 | `cancel_task()` 先 `ready()` 并写“已取消”，随后 `finished` 回调还会再走一遍 | 加任务 token/`cancel_requested` 标志；`finished` 识别取消后只清理、不弹失败框、不改状态；临时目录在取消路径显式清理，启动时清扫残留 `qt_tasks/task_*` |
| 真实 FITS 在 GUI 线程里 base64 编码 | `run_fits()` 对每个文件 `read_bytes()` + `b64encode` | 本地 QProcess 直接传文件路径；base64 只保留给 Web API 上传。避免大 FITS 卡 UI 和双倍内存 |
| Windows 专用打开日志 | `os.startfile()` | 改用 `QDesktopServices.openUrl(QUrl.fromLocalFile(...))`，兼容 Linux/WSL |
| 任务协议无版本 | job/result JSON 只有 payload | job 增加 `schema`/`task_id`，result 增加 `schema`/`elapsed_s`/`error_code`；worker 启动时校验 |
| 无打包文件/版本号 | 仓库无 `pyproject.toml`、`.spec`、`__version__`；PyInstaller 命令只在文档里 | 提交 `pyproject.toml` + `desktop/TelescopeEngineering.spec`；窗口/日志写版本号，支持 `--version` |
| 桌面依赖含 WebView | `requirements-desktop.txt` 仍有 `pywebview` | Qt 已不用 PyWebView，移除并固定 PySide6 版本；分析类依赖留在 requirements-optional |

验收：

- `--worker pd --job ... --result ...` 在未安装/未 import PySide6 的解释器下可运行；
- 取消一个耗时任务后：无失败弹窗、状态为“已取消”、`qt_tasks/` 无残留；
- offscreen smoke 连续运行两次结果一致；
- EXE `--self-test` / `--version` 通过。

### P5-4 魔法数收口：仪器参数只定义一次

当前散落位置：


建议：

1. 建 `products/instrument.py`（或 `configs/instrument.yaml` + dataclass），集中
   口径、遮拦比、波长、仿真尺寸、默认目标；
2. 在边界处校验（半径 > 0、`0 ≤ obscuration < 1`、波长 nm、帧数为正），

验收：上述文件不再出现裸 `1250.0`/`0.28`/`632.8`（测试期望值除外）；
参数校验有单元测试。

### P5-5 测试布局与 CI 补口

现状：

| 问题 | 证据 |
|---|---|
| 产品测试放在 Web 目录 | `web/tests/test_product_modules.py`、`test_sensitivity_service.py`、`test_zemax_fea.py` 实际测 `products.*` |
| Web 根目录的 `test_*.py` 不是单元测试 | `web/test_api.py`、`web/test_ccd.py`、`web/test_framework.py` 是依赖本地服务的 HTTP 脚本，`discover -s web/tests` 不会运行 |
| 桌面只有手写 smoke | `desktop/qt_smoke.py` 未进 CI |
| 无 lint/类型检查 | CI 只有 CMake/CTest 和 `unittest` |
| CUDA 从不编译 | CI 的 CMake job 均未开启 `-DTEL_BUILD_CUDA=ON` |

建议：

1. 测试按被测层放：`products/tests/`、`desktop/tests/`、`pipeline/tests/`、
   `tests/python/integration/`；HTTP 脚本移到 `scripts/smoke/` 并标记为手工集成；
2. CI 增加四个门：
   - `desktop-smoke`：安装 PySide6 + `QT_QPA_PLATFORM=offscreen` 跑
     `desktop/qt_smoke.py`；
   - `python-tests`：跑 `products/tests`、`pipeline/tests`、`desktop/tests`；
   - `lint`：`ruff check`（后续可加 `mypy products desktop`）；
   - `cuda-compile`：用 `nvidia/cuda:12.x-devel` 仅编译
     `-DTEL_BUILD_CUDA=ON`，防止 nvcc/kernel 代码长期失修（GPU 运行测试可留自托管）；
3. 主算法 `0.001667λ`、FEA/PD 柱状图关键字段作为回归断言，重构 PR 必须保持。

验收：删除/迁移 `web/tests` 后 CI 仍全绿；QT offscreen smoke 在 CI 稳定通过；
一次故意改坏 PD 目标函数的 PR 能被 `python-tests` 抓住。
