# 目录与模块架构

> 版本：v1.1 · 2026-11
> 目标：把目录收敛到“数据 → 反演 → 灵敏度/控制”三层，删除构建/历史结果，代码与文档一一对应。

## 1. 顶层目录

```text
telescope_gpu/
  include/telescope/       主项目 C++ 头文件（相位差/FFT/Zernike/FITS/config）
  src/                     主项目 CPU/CUDA 实现
  apps/                    forward_generate / inverse_solve
  tests/                   主项目 CTest
  configs/                 default.conf / pipeline.json
  pipeline/                CCD 星场、定标、检测、天体测量
  products/sensitivity/    FEA case → 面形 → Zernike → 环境 S
  framework/               通用反演/控制 C++ 契约 + demo
  numerics/                Eigen/GTest/Benchmark/pybind11 数值库
  ml/                      可微前向、CNN、传统对比、two-stage
  web/                     兼容 wrapper（旧 API/UI 已归档）
  products/jobs/store.py   SQLite 作业队列（3A/PD）
  scripts/zemax_zos_worker.py  Windows/OpticStudio worker
  data/fea_cases/          合成 FEA 参考工况（可替换真实导出）
  docs/                    架构/模块/教程/技术报告
  scripts/                 可视化/检查脚本
  Dockerfile / .github/    构建与 CI
```

**已删除/不再提交**：`build*/`、`results/`、`baseline/`、`data/ccd_pipeline/`、`web/serve.py`、`web/index.html`。这些都可重新生成，避免仓库膨胀。

## 2. 三条数据流

### 2.1 主项目：相位差

```text
configs/default.conf
  -> forward_generate (CUDA)
  -> star_field_*.fits
  -> inverse_solve
  -> PhaseDiversitySolver
  -> inverse_result.txt
```

入口：`apps/forward_generate.cu`、`apps/inverse_solve.cu`
核心：`src/forward_model.cu`、`src/phase_diversity.cu`
结果：45° 0.001667λ、5692 次评估（见 `docs/技术报告_代码对齐版_v2.docx`）。

### 2.2 CCD / PD 产品

```text
pipeline/ (simulate/preprocess/detect/astrometry)
  -> products/ccd/service.py        (合成 CCD + 定标 + PSF)
  -> products/ccd/fits_service.py  (真实 FITS → PSF)
  -> products/pd/service.py             (PD/BOBYQA 并行多起点)
  -> desktop/qt_app.py              (Qt 桌面入口；旧 API 归档)
  -> desktop/gui.py             (⑤/⑥)
```

模块 1 文档：`docs/模块1_CCD数据管线.docx`
模块 2 文档：`docs/模块2_相位差反演.docx`

### 2.3 灵敏度 / 控制产品

```text
data/fea_cases/ + products/sensitivity/
  -> desktop/qt_app.py (Qt FEA 页签)
  -> products/control/service.py                    3C 代理
  -> products/sensitivity/matrix_service.py          自定义 S
  -> desktop/gui.py (③A/③B/③C)
```

模块 3 文档：`docs/模块3_灵敏度与控制.docx`
参数解释：`docs/参数与控制量对照.md`

## 5. 构建/复现

```bash
# 主项目 CPU 测试
cmake -S . -B build -DTEL_BUILD_CUDA=OFF
cmake --build build -j4 && ctest --test-dir build --output-on-failure

# 通用框架
cmake -S . -B build-framework -DTEL_BUILD_CUDA=OFF -DTEL_BUILD_FRAMEWORK=ON \
  -DTEL_BUILD_NUMERICS=ON -DTEL_NUMERICS_BUILD_TESTS=OFF \
  -DTEL_NUMERICS_BUILD_BENCH=OFF -DTEL_NUMERICS_BUILD_PYTHON=OFF
cmake --build build-framework -j4
ctest --test-dir build-framework -R framework --output-on-failure
./build-framework/framework/framework_demo results/framework

# Web
python desktop/qt_app.py
python3 -m unittest discover -s web/tests -v
```

## 6. 注释约定

- **Python**：模块 docstring 写“数据流/输入输出/单位”；公开函数写参数/返回/异常；算法步骤编号。
- **C++/CUDA**：文件头写模块职责；函数前写输入/输出/异常；kernel 写线程映射/共享内存。
- **JSX/HTML**：每个大区块前写 `{/* ... */}` 或 `<!-- ... -->`，标明阶段/数据来源。
- 注释解释“为什么/边界”，不复述代码。

## 7. 目录体积策略

- 构建产物、结果、历史 baseline 不入库；
- 大 FITS/Word/PDF 只保留必要样本；
- 真实 FEA/Zemax 私有文件不进公开仓库，只提交 schema/说明；
- 新增目录先在 `docs/目录与模块架构.md` 登记，再写代码。
